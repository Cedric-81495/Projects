# GWOP University — changes applied 2026-08-18

This folder is complete and ready to push. Replace the contents of
`GWOP-ORG/gwop-university/` in your repo with everything here.

Two build failures that occurred earlier are already fixed in this version — see

## After unzipping — three steps

**1. Install dependencies**

```
npm install
```

Includes `@types/qrcode`, which `/sign` needs. Without it the build fails on
TS7016.

**2. Run the new migration**

Supabase → SQL Editor → paste `supabase/migrations/0008_leads.sql` → Run.
(If you already ran it, skip — the file is unchanged.)

**3. When Jake sends the webhook URL**

Vercel → Environment Variables → **Preview AND Production**:

```
GHL_WEBHOOK_URL=https://services.leadconnectorhq.com/hooks/...
```

Server-only. Never prefix with `NEXT_PUBLIC_` — it is an unauthenticated write
endpoint into the client's CRM, and in client JavaScript anyone could flood it.

Until it is set, forwarding no-ops, leads accumulate as `pending`, and they
deliver automatically once configured. Nothing is lost by deploying first.

## Build failures fixed

**`z.enum` with a dynamic tuple** — `src/app/api/lead/route.ts` used
`z.enum([...values] as [string, ...string[]])`. TypeScript cannot verify that
cast because `.map()` returns a mutable array. Replaced with a `Set` plus a
`.transform()`, which is also better behaviour: an unknown interest now falls
back to `unspecified` instead of rejecting the whole request. A stale QR
parameter must never cost a signup at the booth — an uncategorised lead is
recoverable, a refused one is gone.

**`z.record` with one argument** — valid in zod 3, a compile error in zod 4, and
this project is on `^4.1.0`. Now `z.record(z.string(), z.string().max(200))`.

**Every-2-minute cron removed from `vercel.json`.** Hobby plans allow two crons
at daily frequency only; a sub-daily schedule is rejected and fails the whole
deployment. The route still exists and can be triggered by hand:

```
curl -H "Authorization: Bearer YOUR_CRON_SECRET" \
  https://your-domain/api/v1/cron/lead-sync
```

Add the schedule back once the plan supports it — before Aug 30, since a
once-daily retry is not useful at a booth.

## Verify after deploying

```
npm install
node_modules/.bin/tsc --noEmit
```

Then confirm the endpoint is live:

```
curl -X POST https://gwop-university-develop.vercel.app/api/lead \
  -H "content-type: application/json" -d "{}"
```

A **400** with validation messages is the correct answer — it proves the route,
the handler wrapper, the rate limiter and the Zod schema are all in place. A
**404** means Vercel's Root Directory is not pointing at this folder.
